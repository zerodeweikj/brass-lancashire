# 平台大厅与进场动效 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把进站落点从「兰开夏房间大厅」改为「zero 的桌游空间」游戏选择大厅，配套 games 清单契约、双主题切换与 coverPush 进场动效。

**Architecture:** 三层——平台壳（GameHub 大厅，暖白）/ 通用房间层（现有 Lobby，零改动复用）/ 游戏模块（兰开夏，自带主题与进场美术）。平台壳只认 `GET /api/games` 的 manifest，不认具体游戏。

**Tech Stack:** FastAPI + SQLAlchemy(双库) / Vite + 原生 JS + Phaser / Playwright e2e / server 进程内 TestClient 冒烟

**Spec:** `docs/superpowers/specs/2026-09-19-平台大厅与进场动效-design.md`

## Global Constraints

- 改后端必重启；改前端必 `cd web && npm run build`（vite emptyOutDir:false），构建后用 `grep -o '<特征串>' web/dist/assets/*.js` 验证非假成功
- 引擎测试用 `server/.venv/Scripts/python.exe tests/<t>.py`；前端 e2e 用 `cd web && node tests/<t>.mjs http://127.0.0.1:8765`
- e2e 房名必须加 `+ rnd` 后缀（房间存 SQLite 跨测试残留）
- 账号测试用唯一用户名（`'X'+时间戳后5位`），防 409 撞库
- 进程内测试范式：先 `db.DB_PATH=临时文件` 再 `from app.main import app`
- `h()` 加类唯一可靠方式 = spec 里 `.class` token
- 用户内容一律 textContent 注入（防 XSS）
- 中文 UI 文案；正式名「工业革命·兰开夏」，禁止写「商战」

**Interfaces:**
- Consumes: `api.games()`、`session.joinRoom`、`setTheme`、Task 8 的 `Transition.enterGame(cardEl, manifest)`
- Produces: `class GameHub { mount(host), unmount(), }`；DOM 契约：`#gamehub .gh-card[data-game-id]`、`.gh-card.locked`（灰卡）、`.gh-skel`（骨架）、`.gh-err`（失败态）、`#gh-code-input`、`#gh-code-err`

行为（对照 spec 第 4/7 节）：
- 进站 `setTheme(null)` → `body.theme-platform`；标题「选一款桌游开始吧」+ 副文案
- 卡片字段渲染；`status==='available'` → 主按钮「进入游戏」+ 次级「AI 陪练房」；`coming/dev` → 整卡 `.locked`（cursor:default、tabindex=-1、无 hover、无 onclick）
- 加载中 → 2 张骨架卡 `.gh-skel` + 「服务唤醒中…」；失败 → `.gh-err`「游戏库加载失败」+ 重试按钮
- 顶栏房间号 + 加入：调用 `session.joinRoom(code, name)`；成功由 app 路由；失败把 e.message 写 `#gh-code-err`（内联红字，不弹窗）
- 文案/输入一律 textContent（h() 的 text 属性）

- [ ] **Step 1: 实现 GameHub.js + 样式**
- [ ] **Step 2: build + grep `gh-card`**
