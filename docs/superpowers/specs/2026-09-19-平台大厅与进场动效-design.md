# 平台大厅与进场动效 · 设计文档

- 日期：2026-09-19
- 状态：已获用户确认（待实施）
- 范围：把「兰开夏专用站」改造为「zero 的桌游空间」的第一步——游戏选择大厅、平台/游戏双主题、进场过渡动效、游戏清单数据契约

## 1. 背景与目标

初衷是做一个**桌游平台**，现状是只有兰开夏一个游戏。本次改造的目标：

1. 新增**游戏选择大厅**：玩家进站的落点，负责且只负责"挑游戏"
2. 平台壳与游戏**视觉彻底分家**：暖白 + 墨绿平台壳，进入游戏切换为游戏专属主题（兰开夏＝深色工业风），制造反差感
3. 大厅 → 游戏有**过渡动效**（必选，不做直接跳转），动效同时承担素材加载遮罩职责
4. 确立**游戏清单数据契约**，让后续接新游戏零平台代码改动

已盘点：现有房间/观战/聊天/账号/战绩/反馈均为平台级资产，可直接复用；兰开夏专属仅 5 个接口（action/end-turn/preview/static-data/cheat）+ engine 包 + 前端场景。

## 2. 三层架构

| 层 | 内容 | 主题 |
|---|---|---|
| 平台壳 | 大厅（选游戏）、顶栏（账号/战绩/房间号）、留言、登录注册 | 暖白 `#F6F3EE` + 墨绿 `#1F6F5C` + 深墨 `#1C1B19` |
| 通用房间层 | 房间列表、座位、准备、观战、聊天、建房/加入 | 跟随游戏主题 |
| 游戏模块 | 引擎 + 前端场景 + 素材 + 主题变量 + 进场动效美术（兰开夏为第一个） | 各自独立 |

铁律：**平台壳不认识任何游戏**，只认 `gameId` 和游戏清单 manifest。新增游戏 = 放资源目录 + 写 manifest，平台代码零改动。

## 3. 数据契约

### 3.1 游戏清单

`GET /api/games` 返回数组，每项：

```
gameId        字符串，如 'brass'
name          显示名，如 '工业革命·兰开夏'
cover         封面图路径（3:2 横版，≥1200px 宽）
minPlayers    最少数
maxPlayers    最多数
duration      约多少分钟
weight        '轻' | '中' | '重'
tagline       一句话卖点
tags          字符串数组，如 ['支持观战', '游客可玩', 'AI 陪练']
status        'available' | 'coming' | 'dev'（coming/dev 渲染为灰卡）
transition    { template, duration(ms), accent } —— 见第 6 节
```

### 3.2 房间与战绩挂 gameId

- `rooms` 增加 `game_id` 字段；`POST /api/rooms`（建房）body 必带 `gameId`
- 顶栏「房间号加入」→ 加入接口响应中回 `gameId` → 前端跳对应游戏的房间列表
- `game_results` 增加 `game_id` 列（Neon 需加列迁移），战绩将来按游戏筛选

### 3.3 游戏资源目录规范（锁死）

```
web/public/games/<gameId>/
  cover.webp    封面 3:2，≥1200px 宽
  hero.webp     进场宽幅 16:9，≥1920px 宽
  theme.css     该游戏主题变量
```

## 4. 大厅设计（已定稿 v3）

- 标题文案：**「选一款桌游开始吧」**（已定），副文案「目前开放 1 款，更多正在路上」
- 顶栏：logo（圆角方块 z）+ 站名「zero 的桌游空间」、战绩、**房间号输入 + 加入按钮**、头像
- 游戏卡：封面 + 名称 + 「2–4 人 · 约 60 分钟 · 重度策略」+ 一句话卖点 + 标签 chip + 主按钮「进入游戏」+ 次级按钮「AI 陪练房」（降新人门槛）
  - 「进入游戏」→ 落到该游戏的房间列表
  - 「AI 陪练房」→ 直接创建该游戏的机器人陪练房并进入（游客可用，行为与现有「陪练」勾选一致）
- 情书卡：**整卡灰化不可点**（`cursor: default`、无 hover、无 tab 焦点、无任何反馈），「暂未开放」灰色标签 + 右上角「开发中」
- 虚线「敬请期待」占位卡
- 底部：「留言 / 提意见」纯文字链接（无框，沿用现状）+ 版本号
- 大厅**不放**「进行中的房间」面板；不设游戏详情页

## 5. 页面流转（A 方案，已定）

```
大厅（暖白）──点卡──> 该游戏的房间列表（建房/加入/观战/AI 陪练，平台通用层）──开局──> 对局（深色）
顶栏「房间号 + 加入」──服务端回 gameId──> 直接落到对应游戏的房间列表
```

不做详情页。反差不只靠颜色：大厅稀疏留白、信息密度低；进入游戏后信息变密、节奏变紧。

## 6. 进场过渡动效

### 6.1 原则

- **动效必须做**，且同时承担素材加载遮罩职责（398 张素材未就绪就揭幕 = 闪白/闪空画布）
- **每个游戏都有专属进场动效**：表现形式的代码（模板）可以一样，**美术资源绝不共用**——封面、宽幅背景、主题色、时长、主色调全由游戏自带，反差正来自这里

### 6.2 平台层：Transition.js 模板播放器

```
Transition.js
  enterGame(cardEl, manifest)   大厅 → 房间列表（快过渡 ~400ms）
  enterMatch(manifest)          房间列表 → 对局（重过渡 1.5–2s，含加载进度）
  exitToLobby()                 反向过渡 ~300ms
```

`templates/coverPush.js`（封面推近）为首个模板；横向滑入、卷轴展开仅留接口位置，不接代码。时长/缓动集中为常量。

### 6.3 coverPush 实现要点

1. **主题色切换**：三层变量模型——`:root` 中性暗色默认（兜底）；`body.theme-platform` 平台壳（暖白，变量覆盖）；`body.theme-brass` 兰开夏（由 `games/brass/theme.css` 提供变量覆盖；将来每个游戏自带 `theme-<gameId>`）。`body { transition: background-color .6s }`；换 class 即平滑插值，不用 JS 逐帧改色。进入游戏 = 移除 `theme-platform`、挂 `theme-<gameId>`；回大厅 = 反向。
2. **FLIP**：点击瞬间记录封面卡 `getBoundingClientRect()` → 过渡层把封面摆在原位 → 下一帧 transform 平移+放大至全屏；只动 `transform/opacity`，`requestAnimationFrame` 触发类名；~520ms，`cubic-bezier(.22,.61,.36,1)`；大厅容器同时 `scale(0.98)+opacity:0` 内缩
3. **防闪三件套**：等 Phaser 首帧就绪事件再揭幕；canvas 底色预设深色；Phaser 在过渡层下方先初始化
4. **交互**：动画期间整页 `pointer-events:none` + 按钮 disable；结束移除 `will-change`
5. **可访问性**：`prefers-reduced-motion: reduce` → 降级 150ms 纯淡入
6. **降级**：`hero.webp` 404 或 manifest 缺 transition 块 → 退回纯色淡入 300ms，绝不白屏

### 6.4 时间线（一次完整进场，约 1.7s）

```
0s     锁定交互
0–0.5  封面 FLIP 放大（520ms）
0–0.6  主题色暖白 → 深色（600ms）
0.2–1.5 素材预加载（被动效遮住）
0.3–1.5 Phaser 首帧就绪
1.5–1.7 揭幕淡出（200ms）
```

## 7. 状态、边界与错误处理

| 状态 | 处理 |
|---|---|
| 清单加载中（Render 冷启动） | 暖白骨架卡 + 「服务唤醒中…」，不用转圈 |
| 清单加载失败 | 「游戏库加载失败」+ 重试按钮，不留白屏 |
| 未登录 | 主按钮「登录后进入」；AI 陪练房允许游客（沿用现状） |
| 灰卡 | 不可交互（见第 4 节） |
| 房号填错 | 顶栏下方内联红字「房间不存在或已解散」，不弹窗 |
| 刷新页面 | 回大厅，不回上次游戏 |
| 手机端 | 卡片单列；顶栏房间号折叠为图标 |

## 8. 验收标准（e2e 断言）

### 大厅

1. 大厅渲染出 N 张游戏卡，字段与接口一致
2. 点「进入游戏」→ 落到该游戏房间列表且 gameId 正确
3. 点灰卡无任何反应/跳转/焦点变化
4. 顶栏输入有效房号 → 跳对应游戏房间列表；无效 → 内联报错
5. 清单接口 500 → 失败态 + 重试可恢复
6. 进入游戏后 `body` 挂 `theme-brass`，CSS 变量整套切深色
7. 375px 宽度下卡片单列、无横向溢出

### 动效

8. 点击后立刻出现过渡层，重复点击不产生第二个房间
9. 过渡期间 body 背景色采样不到白色
10. 过渡结束：`body` 带 `theme-brass`、大厅 DOM 已卸载、房间列表可见
11. `prefers-reduced-motion` 模拟下动画 ≤150ms 且无缩放位移
12. 对局揭幕时 canvas 已完成首帧（像素非纯色）
13. 退出回大厅有反向过渡，结束时 `body` 不带 `theme-brass`

## 9. YAGNI（明确不做）

搜索/筛选、好友列表与在线状态、游戏评分、"最近玩过"、游戏详情页、横向滑入/卷轴展开模板代码、游戏内聊天以外的社交功能。
