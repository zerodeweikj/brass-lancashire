# 工业革命·兰开夏（Brass: Lancashire）局域网联机版

本地可运行、支持 **局域网多设备联机** 的网页移植。严格照官方规则书实现：完整运河 + 铁路两个时代，2~4 人。**服务器权威**架构（单台本地后端持有全部状态，各设备只拿自己视角的裁剪数据）。

## 技术栈

- 前端：`web/`（Phaser 3 画棋盘 + 原生 DOM 覆盖层 UI，Vite 构建）
- 后端：`server/`（Python FastAPI + SQLite，长轮询同步）
- 通信：前端只存 `token`，`playerId` 由后端按座位解析（防伪造）；`rev="房间修订.对局版本"` 长轮询准实时同步。

## 一、启动（开发机，仅需运行一次）

需要 Python 3.11+ 与 Node 18+。

### 方式 A：双击 `start.bat`（日常推荐）

1. 首次使用先按下方「方式 B」完成前端构建（`npm run build`），之后无需再构建。
2. 双击根目录 `start.bat`：自动检查虚拟环境与构建产物、启动后端（`0.0.0.0:8765`）、列出本机局域网访问地址，并自动打开本机入口 `http://127.0.0.1:8765`。
3. 关闭该窗口即停止服务。

### 方式 B：手动命令

```powershell
# 1) 构建前端（每次改了 web/src 后都要重建）
cd web
npm install        # 首次
npm run build      # 产物输出到 web/dist，后端直接托管

# 2) 起后端（同一台机器，监听 0.0.0.0 才能被局域网其他设备访问）
cd ../server
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8765
```

后端就绪标志：`curl http://127.0.0.1:8765/api/health` 返回 `{"status":"ok","engine":"ready",...}`。
打开 `http://127.0.0.1:8765` 即为本机入口。

> ⚠️ 端口说明：本项目固定用 **8765**。旧原型 `D:\zhuoyouyizhi` 常驻 8000（那是它自己的服务，与本项目无关，勿混）。
> 本项目 server 必须绑 `--host 0.0.0.0` 才能被局域网其他设备访问。

## 一之二、停止服务

两种方式任选：

- **方式 1（推荐）：双击根目录 `stop.bat`**——自动找到占用 8765 端口的进程并结束，无需关窗口。
- **方式 2：直接关掉 `start.bat` 打开的那个命令行窗口**（或在窗口里按 `Ctrl+C`）——uvicorn 是前台进程，窗口关闭即停服。

两种方式都会干净地终止服务，已建好的房间/对局数据仍保留在 `server/lancashire.db`（下次启动可继续，除非手动删库重置）。

## 一之三、查看本机局域网 IP

最简单：双击 `start.bat` 启动后，它会自动列出本机所有 IPv4 地址（形如 `192.168.x.x`、`10.x.x.x`、`172.16~31.x.x`），挑一个给队友即可。

也可手动查：
```powershell
ipconfig | findstr "IPv4"
# 只看 WiFi 网卡：
Get-NetIPAddress -AddressFamily IPv4 -InterfaceAlias *Wi-Fi* | Select-Object IPAddress
```
或访问 `http://127.0.0.1:8765/api/health`，其中的 `lan` 字段也列了所有可用 IP。

> 避开 `169.254.x.x`（没真正连上网时系统自动分配的 APIPA 地址，队友连不上）；优先用 `192.168 / 10 / 172.16~31` 段。

## 一之四、家用 WiFi 安全说明

- 局域网 IP（上述私有段）**不会暴露到公网**：家用路由器 NAT 默认不把 8765 端口转发到互联网，外面的人连不进来。
- 能访问服务的只有**连了同一 WiFi 的设备**（家人/室友的手机电脑）——而这正是联机所需，无妨。
- 唯一注意：**不要在路由器上给 8765 做端口转发 / DMZ / UPnP 暴露**，那才会把服务放到公网。家用默认都不开，确认没动过即可。
- 游戏走 HTTP 明文，但只传游戏状态（无账号密码支付），同 WiFi 内风险极低。

## 二、队友加入（同一局域网的其他设备）

1. 房主在游戏大厅点「创建房间」，记下房间号（如 `1DF4E5`）。
2. 队友在自己设备的浏览器打开 **`http://<房主机局域网IP>:8765`**。
   - 房机局域网 IP 看 `start.bat` 启动时的打印，或访问 `http://127.0.0.1:8765/api/health` 里的 `lan` 字段（如 `192.168.31.165`）。
   - 也可直接用房机在局域网内的主机名，例如 `http://DESKTOP-XXXX:8765`。
3. 队友在「房间列表」里点对应房间号旁的「加入」，或直接在③输入房间号加入。
4. 至少 2 人、全员点「准备」后，**房主**点「开始游戏」。

## 三、操作

- 六类行动：`建造 / 双牌建造 / 修路 / 发展 / 出售 / 贷款`，外加 `跳过 / 撤回 / 结束回合`。
- 建造/修路/出售：先点行动按钮 → 地图高亮合法落点 → 点目标 → 选手牌 → 确认费用明细 → 执行。
- 行动点用完或手牌为空时自动结束回合；也可手动「结束回合」。
- 视角过滤：只能看到自己的手牌与抽牌堆，他人手牌与远端市场牌库不下发。

## 四、自测

```powershell
node tests/e2e_web.mjs http://127.0.0.1:8765
```

用 Playwright 模拟 3 台设备，跑完整闭环（33 项断言）：
建房→三端加入→开局→地图点选建造→选牌→费用确认→服务器落盘→**三端同步**→视角过滤→回合推进→非当前玩家按钮禁用→跳过→**贷款**（收入轨后退 + 资金增加）→**发展**（弃板块换铁）→**断线重连**（凭本地 token 自动回局）→**房主重开**（回大厅且座位保留）→无 JS 运行时错误。全绿即 `=== 结果：33 通过 / 0 失败 ===`。

> 脚本自管理后端：若 `BASE` 没有本项目引擎（校验 `/api/health` 的 `engine:ready`），会自动拉起 `server/.venv` 的 uvicorn（`0.0.0.0:8765`），跑完自动关闭。校验 `engine:ready` 字段可避免误连到占用同端口的其他服务。

## 五、重置房间数据

房间与对局存于 `server/lancashire.db`。需彻底清空时：停掉后端 → 删除该文件 → 重启后端（表结构会自动重建）。
